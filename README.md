# Reference Verifier

영문 논문 PDF에서 참고문헌을 추출하고 Crossref·DataCite·arXiv 등록정보와 대조하는 한국어 웹앱입니다. AI는 선택적으로 **인용 문장과 등록된 초록**을 비교합니다. 현재는 초기 개발 버전이며, 모든 논문의 존재나 인용의 타당성을 확정하는 서비스가 아닙니다.

## 실행

Python 3.12 이상과 [uv](https://docs.astral.sh/uv/)가 필요합니다.

```bash
cd /workspace/reference_verifier
UV_CACHE_DIR=/workspace/.cache/uv uv sync --frozen
.venv/bin/python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

기본 포트는 8000입니다. 현재 구성은 **개인 개발용 단일 프로세스**입니다. 결과를 프로세스 메모리에 저장하므로 여러 worker로 실행하면 안 됩니다. 외부 공개 전에는 인증, 요청·업로드 크기 제한, 작업 큐, 저장소, PDF 파서 프로세스 격리가 필요합니다.

네트워크에서 `api.crossref.org`와 `api.datacite.org`, `export.arxiv.org`의 HTTPS 접근을 허용해야 합니다. 기본 검증에는 API 키가 필요하지 않습니다. 이 환경의 네트워크 설정 초안에는 도메인을 추가했지만, 설정 적용·게시 전에는 실제 조회가 차단될 수 있습니다.

### 선택적 AI 설정

`REFERENCE_AI_API_KEY`를 안전한 환경변수/환경 설정으로 제공하고 서버를 다시 시작합니다. `OPENAI_API_KEY`가 이미 주입되어 있다면 그것도 사용할 수 있습니다. 비밀값을 소스나 Git에 넣지 마세요.

- API: `https://api.openai.com/v1/chat/completions`
- 기본 모델: `gpt-4.1-mini`
- 모델 변경: `REFERENCE_AI_MODEL`
- 추가로 필요한 네트워크 도메인: `api.openai.com`
- 키가 없으면 서지정보 검증만 사용 가능합니다. 모델 이용 권한과 API 비용은 별도입니다.

AI 옵션을 켜면, 서지정보가 일치하고 초록이 있는 항목에 한해 인용 문장과 초록을 외부 API로 보냅니다. PDF 전체는 보내지 않습니다. 원문이 아닌 초록만 검토하며, 근거 인용문이 실제 초록에 없으면 판단을 `근거 부족`으로 낮춥니다. 항목당 최대 20개 인용 문맥을 비교하고 검토한 수를 표시합니다.

## 검증 범위

| 항목 | 현재 동작 |
| --- | --- |
| PDF | 텍스트 PDF, 20MB / 300페이지 / 참고문헌 200개 제한 |
| 추출 | References, Bibliography, Works cited, 참고문헌 제목 아래 번호형·저자–연도형 항목 |
| 실재 여부 | Crossref DOI 조회 → 미등록 DOI는 DataCite 추가 조회 → Crossref 서지정보 검색; 두 등록기관에 없는 자료는 확인 불가 |
| 제목 | 대소문자·구두점을 정규화한 제목 유사도 대조 |
| 저자 | 이니셜 우선·성씨 우선·전체 이름 표기와 악센트 차이를 고려해 저자 영역의 성씨·순서 확인; 이니셜/동명이인/축약형의 완전 검증은 미지원 |
| 연도 | 온라인·인쇄 발행연도 모두 고려 |
| 본문 연결 | 대괄호 숫자 인용, 범위 인용, 일부 저자–연도 인용 |
| 내용 검증 | 선택적 AI 초록 비교; 전체 원문 의미 검증은 미지원 |
| 수정 제안 | 등록정보 기반 일반 서지 표기; APA/IEEE 양식 완전 준수 보장 없음 |
| 출력 | 항목별 근거, 의심 사항, 본문 문맥, JSON 보고서 |

‘주요 정보 일치’는 추출된 표기가 등록정보와 대체로 맞는다는 의미입니다. 학술적 신뢰성이나 인용 주장의 타당성을 보장하지 않습니다. ‘검색 후보’는 동일 논문으로 확정하지 않은 결과입니다. ‘조회 실패’는 네트워크·외부 서비스 실패이며, ‘미확인’은 충분한 등록정보를 찾지 못한 경우입니다. 둘 다 허위 논문이라는 뜻이 아닙니다.

다단 편집·페이지 머리말·특수 참고문헌 양식은 누락/병합을 일으킬 수 있습니다. 추출 항목 수와 원래 PDF를 반드시 비교하세요. 위첨자·각주·복잡한 저자 인용, 스캔 OCR, 전문 수집, 철회/정정 정보의 포괄적 조회, DOI가 없는 자료의 DataCite 검색은 아직 지원하지 않습니다.

## 데이터 처리

PDF 원본은 디스크에 저장하지 않습니다. 추출된 참고문헌은 Crossref로 전송하고, 결과와 인용 문맥은 서버 메모리에 보관합니다. 완료 후 30분이 지난 결과는 다음 작업/결과 요청 때 정리됩니다. 서버를 재시작하면 모두 사라집니다. 보고서 JSON은 필요할 때 직접 다운로드하세요. 동시에 두 PDF, 전체 최대 네 개의 외부 요청을 처리합니다. 결과 ID를 아는 사람은 결과를 조회할 수 있으므로 현재 서버를 공개 서비스로 배포하지 마세요.

## 테스트

```bash
cd /workspace/reference_verifier
.venv/bin/python -m pytest -q
node --check app/static/app.js
```

테스트는 생성한 PDF와 모의 Crossref/AI 응답을 사용합니다. PDF 추출, 인용 연결, DOI 대조, 애매한 검색 후보, 잘못된 DOI, 네트워크 실패, AI 근거 인용문 검사, 업로드→결과→보고서 흐름을 검증합니다. 실제 외부 API 연결 및 실제 AI 품질 평가는 별도입니다.

## 구조

- `app/parsing.py`: PDF 좌표·단·들여쓰기 분석, 참고문헌 경계 및 서지정보 구조화
- `app/extraction.py`: 파싱 레이어 연결, 식별자 및 본문 인용 추출
- `app/verification.py`: Crossref 조회, 서지정보 대조, AI 초록 검토
- `app/main.py`: 업로드, 작업 진행 조회, 보고서 API
- `app/static/`: 빌드가 필요 없는 한국어 웹 화면
- `tests/`: 오프라인 재현 가능한 테스트

설정 이후 실제 논문 표본으로 추출 정확도를 평가하고, 전문 확보 및 인용 양식별 정규화를 확장하는 것이 다음 단계입니다.

### 정확도 개선

검색 후보는 제목·첫 저자·발행연도를 함께 고려하며 짧고 흔한 제목은 가중치를 낮춥니다. 중복 DOI 후보는 제거하고, 모호한 경우 여러 후보를 화면에 표시합니다. DOI가 Crossref에 없으면 DataCite도 확인하며, DataCite 접속 실패가 기존 Crossref 검색을 막지 않습니다. 네트워크 차단·요청 제한·시간 초과는 논문 미확인과 구별합니다. 회귀 테스트는 일반 저자 표기, 잘못된 저자 순서, 제목에만 등장하는 성씨, 악센트 변형, 후보 순위 및 등록기관 추가 조회를 포함합니다. 실제 논문 표본에 대한 정확도 수치는 아직 측정하지 않았습니다.

### 미확인·확인 필요가 많을 때

화면의 **검색 연결 점검**을 누르면 Crossref와 DataCite 접근 가능 여부를 각각 확인합니다. 입력 논문은 보내지 않고 고정된 공개 요청을 사용합니다. 연결 정상은 논문 검증 정확도를 뜻하지 않습니다.

결과의 **검증 단계별 결과**는 입력 DOI 등록 확인, 제목·첫 저자·연도 대조, 서지 표기 경고, AI 초록 검토를 분리합니다. DOI 등록은 해당 DOI가 존재한다는 뜻이며, 인용된 논문과 같은 논문인지 또는 인용 주장이 옳은지 보장하지 않습니다. 검색 미해결·외부 조회 실패·애매한 검색 후보도 별도로 집계합니다. 여러 DOI가 한 항목에 포함되면 추출 점검 경고를 표시합니다.

화면에 `0.4.0-layout-parser` 버전이 보이지 않으면 최신 코드를 받은 뒤 서버를 재시작하세요. 기존 결과에는 새 진단 정보가 없을 수 있으므로 PDF를 다시 처리하세요. 문제 재현 시 **JSON 보고서**와 해당 PDF를 함께 확인해야 추출 누락, 데이터베이스 미수록, 매칭 오류를 구분할 수 있습니다. 보고서에는 참고문헌과 본문 인용 문맥이 들어 있습니다.

이 버전은 실패 원인을 드러내는 진단 개선을 포함합니다. 일치 임계값을 낮추지 않았으며, 사용자의 실제 논문에 대한 정확도 향상이 검증되었다고 주장하지 않습니다.

### 첨부 보고서에서 재현한 분리 오류 수정 (0.3)

영문 저자–연도형 참고문헌에서 발행연도가 줄 끝으로 밀리면, 기존 분리기는 여러 논문을 합치고 저자 목록 중간을 새 항목으로 잘랐습니다. 이제 세미콜론 저자 목록과 연도 전체를 문맥으로 인식해 줄바꿈과 관계없이 경계를 찾습니다. 번호형 및 기존 다른 형식은 기존 분리기를 유지합니다. 원문 표기는 보존합니다.

사용자가 첨부한 저장 HTML의 24개 그룹과 앞부분 누락 경고를 이어 붙인 참고문헌 텍스트에서 **31개 항목, 17개 arXiv ID**를 복원했습니다. 이것은 저장 HTML의 텍스트에 대한 재현 결과이며, 원본 PDF를 재추출한 결과나 논문의 실재 여부 검증 수치가 아닙니다. 짧은 서지정보 발췌를 회귀 테스트에 포함했습니다.

arXiv ID가 있으면 `export.arxiv.org`의 Atom API에서 해당 ID를 먼저 조회합니다. 명시한 버전이 다르면 받아들이지 않습니다. 프리프린트 조회 실패 시 출판본은 별도 후보로만 표시하며, 프리프린트의 연도를 출판본 연도로 자동 정정하지 않습니다. arXiv ID가 없는 프리프린트의 포괄적 검색은 아직 미지원입니다.

외부 요청은 서버의 모든 작업에서 클라이언트·호스트별로 직렬화합니다. Crossref/DataCite는 요청 간 최소 1.1초, arXiv는 3.1초를 두고, 429/일시 장애 시 `Retry-After`와 공유 대기시간을 적용합니다. 30초 초과 제한은 대기 중인 전체 작업을 장시간 막는 대신 조회 실패로 보고합니다. 실패를 ‘논문 없음’으로 판단하지 않습니다. 네트워크 허용 설정과 실제 서비스 정책에 따라 조회 성공 여부는 달라질 수 있습니다.

### 파싱 레이어 (0.4)

파이프라인을 **PDF 좌표 → 참고문헌 블록 → 저자·연도·제목 필드 → 등록기관 조회 → 대조**로 분리했습니다. GROBID 등 외부 서버는 필요하지 않습니다. 기존 pypdf가 제공하는 텍스트 좌표를 보존하고, 반복되는 내어쓰기와 열 위치가 확인될 때 레이아웃 파서를 사용합니다. 신뢰할 만한 들여쓰기 정보가 없으면 기존 텍스트 파서로 전환합니다. 모든 PDF 형식을 완전히 지원한다는 의미는 아닙니다.

사용자는 PDF를 선택하고 **먼저 참고문헌 파싱 결과 확인**을 눌러, 외부 조회 전에 원래 표기와 추출된 저자·제목·연도 및 PDF 페이지를 볼 수 있습니다. API는 `POST /api/parse`이고 `file` multipart 필드를 받습니다. 이 경로는 등록기관/AI를 호출하거나 작업 결과를 저장하지 않습니다. 일반 검증 결과와 JSON 보고서에도 같은 구조화 필드가 포함됩니다.

첨부된 `2609.01016v1.pdf`에서 기존 파서는 37개 항목을 만들었지만, 실제 참고문헌을 누락·병합하고 부록 본문과 소프트웨어 라이선스 표를 섞고 있었습니다. 새 레이어는 **참고문헌 10–12페이지의 51개 항목**을 구조화하고 **13페이지의 A Additional Details on Human**에서 종료했습니다. 실제 원본 PDF 업로드로 미리보기를 확인했습니다. 51개 구조화 성공은 논문 51개의 존재/인용 적절성 검증 성공을 뜻하지 않습니다.

저자 전체 이름과 이니셜을 다루고, 반복되는 성씨는 같은 위치를 중복 사용하는 대신 이름별 순서로 대조합니다. `and 27 others` 같은 정상 축약은 전체 저자를 누락으로 단정하지 않으며, 표시된 저자명의 실제 불일치는 계속 경고합니다. 구조화된 제목은 참고문헌 전체가 아니라 제목 필드끼리 비교합니다. 제목/저자 검색도 분리된 필드를 사용합니다.

회귀 데이터 `tests/fixtures/acl_reference_layout.json`은 해당 PDF의 참고문헌 좌표/텍스트와 부록 시작 한 줄만 담습니다. 원본 PDF는 저장소에 포함하지 않습니다. `saved_html_metadata.json`은 이전 첨부 HTML에 표시된 VoiceCraft·Neural Codec Language Models 등록정보를 옮긴 것으로, 해당 2개 항목의 잘못된 후보 판정이 일치로 바뀌는 것을 재현합니다. 이는 저장된 메타데이터 재생 검증이며 새 실시간 API 조회가 아닙니다. 실제 전체 51개의 검색 성공률이나 의미 검증 정확도는 별도로 평가해야 합니다.
